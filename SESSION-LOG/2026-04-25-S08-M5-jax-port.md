## 1. B-005 Leray Projector Fix

### Root Cause

`numpy.fft.fftfreq(N)` represents the Nyquist frequency as `−N/2` at index `N//2`. Both the mode at index `N//2` and its "pair" fall at the same index, so each has `kx = −N/2`. The Hermitian symmetry requirement for `ifftn` to return a real array is:

```
û(−k) = û(k)*
```

But since both the mode and its pair are at `kx = −N/2` (not `+N/2`), the anti-Hermitian property `k·û(−k) = −(k·û(k))*` is violated for the Nyquist plane. This causes `ifftn` to return a complex field with large imaginary parts (~79 RMS for N=16 random fields). Taking `real(...)` discards the imaginary part, but the divergence escapes.

### Fix

Zero the Nyquist spectral planes **before** applying the Leray corrector:

```python
for f_hat in (u_hat, v_hat, w_hat):
    f_hat[nq, :, :] = 0.0
    f_hat[:, nq, :] = 0.0
    f_hat[:, :, nq] = 0.0
```

This is physically correct: the 2/3 dealiasing rule always zeros these modes in the solver anyway (k_max = N//3 < N//2). The same fix was applied to the JAX port via a `nyquist_mask` (element-wise multiplication).

## 2. JAX Metal Port

### Files Created

- `layer3/route1_3D_jax.py` — JAX-JIT Route 1 3D solver

### Hardware: Apple M5 Metal

jax-metal 0.1.0 is installed with `jax==0.4.26 + jaxlib==0.4.26`. The Metal GPU backend is active (`jax.default_backend() == "METAL"`). However, jax-metal 0.1.0 has two critical limitations:
1. **No complex tensor support** — `complex<f32>` FFTs fail on Metal
2. **No float64 support** — `tensor<f64>` fails on Metal

### Solution

**CPU device routing + float32 throughout:**

```python
if _JAX_BACKEND_RAW == "METAL":
    _COMPUTE_DEVICE = jax.devices("cpu")[0]
    _JAX_BACKEND = "CPU-JIT"

def _d(arr):
    """Move array to compute device (CPU when Metal is default)."""
    return jax.device_put(arr, _COMPUTE_DEVICE)
```

All arrays are placed on the CPU XLA device via `_d()`. `@jax.jit` still applies XLA/LLVM graph fusion → measurable speedup over plain NumPy. When jax-metal adds complex FFT support, only the `_COMPUTE_DEVICE` routing changes.

**No `jax_enable_x64`:** Metal doesn't support float64 either. Float32 gives ~1e-6 relative precision — sufficient for spectral NS. Test tolerances adjusted accordingly.

**Boolean-mask Leray correction (no complex zeros_like):**

The eager-mode dispatch of `jnp.zeros_like(complex_array)` hits Metal's default trace and fails. Replaced with:

```python
valid   = (k2 > 0.0).astype(k2.dtype)          # float32 mask
correction = (k_dot_u / k2_safe) * valid        # complex × float → complex
```

No complex literal creation → safe in eager mode.
